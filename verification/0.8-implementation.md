# 0.8 구현·검증 기록

작성: 2026-09-21 KST. 현재 상태: 0.8 구현·자동 검증·승인된 실제 Discord 시험 완료. 후속 운영 승인을 받아 0.8을 적용했으며 현재 운영 결과는 [운영 검증 기록](0.8-production.md)을 따른다. 아래 최초 검증 기록의 승인 대기 문구는 당시 상태다.

## 후속 승인 시험 완료 — 2026-09-21

아래 결과가 이 문서의 최초 ‘허락 대기’ 상태보다 우선한다. 사용자가 실제 Discord 시험 1건을 명시 승인했고, **06:07 KST에 실제 시험 메시지 1건을 전송했다.**

- 실행: Windows/Node.js에서 운영 미적용 Cloudflare 시험 버전을 업로드하고, 해당 버전에서 0.8 `sendDiscord`와 `buildDiscordTestContent`를 실행했다.
- 시험 전용 비운영 버전 UUID: `b83706df-fef9-4293-a6ef-d4254039a0b3`. 전체 0.8 운영 배포 후보가 아닌, 승인된 한 번의 연결 시험 진입점이다.
- Discord 생성 응답: HTTP 성공, 메시지 ID `1551339013393350737`.
- 생성 후 Webhook 메시지 읽기 API로 다시 조회해 ID와 실제 본문이 보낸 세 줄 메시지와 같은지 확인했다(`contentVerified=true`). 이는 실제 메시지 생성과 본문 저장을 증명하며 사용자가 읽었음을 증명하지 않는다.
- 전송 가능한 HTTP 요청은 한 번만 실행했다. 추가 네트워크 호출은 생성된 메시지의 읽기 확인뿐이며 반복 전송하지 않았다.
- 비밀 값은 기존 Worker의 비밀 바인딩 안에서만 사용했다. 임시 인증 원문은 로컬 메모리에만, 생성 소스에는 해시만 있었다. 생성한 진입점·설정 파일은 삭제했다.
- 임시 인증은 `2026-09-20T21:17:16.377Z`에 만료된다. 만료 전에도 시험 전용 영수증·시도 기록으로 재전송을 막는다. 원격 immutable 버전은 기록으로 남지만 운영에 적용하지 않았다.
- 시험 도구에 한해 기존 KV의 `verification:0.8:discord-test:2026-09-21` 키만 사용했다. 정기 감시 키나 Cursor는 수정하지 않았고 새 0.8 감시 코드의 Durable Object 구조도 바꾸지 않았다. 이 시험용 KV 차단은 분산 잠금 보장이 아니므로 실행 도구 자체가 하나의 승인 요청만 보내고 로컬 시도 기록으로 재실행을 차단한다.
- 업로드·전송 전후 운영 배포 목록이 정확히 같음을 확인했다. 운영은 **0.7 / UUID `0c4fb73b-bf82-42a1-a387-c59a4ee0e17e` / 트래픽 100%**다. Cron을 변경하지 않았다.
- 이번에 추가한 인증·만료·중복 시험을 포함해 Windows 로컬 `npm run check`, **39/39 자동 시험**이 통과했다. 자동 시험의 Discord는 모두 가짜 응답이며 위 한 건만 실제 전송이다.

실제 새 사건을 Cloudflare Cron이 감지해 전체 0.8 경로로 전달하는 시험과 0.8 운영 전환은 아직 하지 않았다. 운영 전환은 별도 버전 승인이 필요하다.

## 구현

- codex-reset.com 공개 JSON 목록만 조회한다. X API·문장 분류·상대 시간 계산·X 복구 스크립트는 활성 소스에서 제거했다.
- 리셋 발표·사용량 확대·알려진 저장형 리셋권 상태만 선택한다. 세 줄 메시지, 발표 시각 KST, 사이트 출처, FixupX 미리보기 링크를 사용한다.
- SQLite Durable Object가 요청을 순서대로 처리한다. 최초 이력 미발송, 상태 전진, 중복 방지, 1시간 제한, 신선도·자료형 검사를 구현했다.
- Discord 요청은 가짜 응답으로 시험했다. 전송 직전 기록과 메시지 ID 영수증, 429 대기, 불명확한 결과의 자동 재전송 차단을 구현했다.
- 기본 발송·연결 시험은 꺼져 있다. `/run`은 읽기 진단이며 `/test-discord`는 별도 설정·인증이 필요하다.
- 기존 미커밋 소스·시험·설정·문서 사본을 `.wrangler/backups/before-0-8-20260921`에 보관했다. 과거 변경을 reset하지 않았다.
- 개발 도구를 Wrangler 4.135.0, Miniflare 5.20260918.0-alpha, esbuild 0.28.1로 고정했다. 기존 개발 의존성의 npm 취약점 경고 4건은 갱신 후 0건이 되었다. Worker 배포 모듈에는 이 개발 도구가 포함되지 않는다.

첫 원격 진단에서는 토큰 제거 명령의 지원되지 않는 옵션을 발견해 고쳤으며 남은 토큰은 즉시 제거했다. 후속 진단에서는 새 토큰이 가장자리 서버에 반영되기 전 401이 나오는 경우를 확인했다. 검증 스크립트는 인증 거절에만 짧게 재시도하도록 고쳤다. 마지막 전체 원격 진단과 토큰 제거는 모두 성공했다. 인증 거절은 API 읽기나 알림 처리에 진입하지 않는다.

로컬 실행 엔진 시험에서 `redirect: error`가 지원되지 않는 것도 확인했다. `manual`로 바꾸고 비정상 HTTP 응답을 검사하므로 다른 주소로 이동하지 않는 요구는 유지된다.

## 멈춘 지점과 다음 실제 시험

사용자가 실제 Discord 시험 전에 멈추고 허락을 요청하라고 명시했다. 따라서 실제 Webhook 요청은 0건이며 시험을 켜지 않았다. 기존 운영의 자체 정기 실행은 이번 검증 범위가 아니며 변경하지 않았다.

허락을 받으면 기존 알림 채널에 아래 세 줄 시험 메시지 **1건**을 보내고 Discord 메시지 생성 응답을 확인한다. 현재 시험판에는 Webhook 비밀 값이 없으므로 승인된 비운영 시험 경로에 기존 비밀 값을 안전하게 연결하는 준비가 필요하다. 비밀 값 자체를 읽어 대화·파일·로그로 복사하지 않는다. 불명확한 응답에서는 자동 반복 전송하지 않는다.

```text
🧪 **Codex 알림 연결 시험 — 실제 리셋 아님**
**시험 시각(KST)**: [실제 시험 시각] KST
출처: https://codex-reset.com/
```

| 남은 범위 | 상태 | 이유·필요한 근거 |
| --- | --- | --- |
| 실제 Discord 시험 1건 | awaiting-user-authority | 사용자가 시험 직전 허락을 명시적으로 요구함 |
| 0.8 운영 전환·실제 Cron 검증 | awaiting-user-authority | 버전별 운영 승인 필요. 시험 허락과 구별 |
| 24시간 운영 관측·새 실제 사건의 전달 지연 | awaiting-external-evidence | 승인된 운영 전환 후의 시간 경과와 실제 사건이 필요 |
| 이전 0.7로 되돌리기·중복 표식 연계 | 미실행 | 현재 운영 전환을 하지 않았음. 기존 코드·원격 비밀 값·KV를 보존했지만 원격 되돌리기는 미검증 |
| X 비밀 값·옛 KV·구독 정리 | 연기 | 되돌리기 기간과 새 경로 안정 확인 전에는 삭제하지 않음 |

허락 전 가능한 구현·로컬 시험·원격 무발송 진단은 완료했다. 이 기록은 실제 Discord 전달이나 운영 전환 완료를 뜻하지 않는다.
