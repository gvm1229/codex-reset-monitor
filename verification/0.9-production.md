# 0.9 운영 배포 및 발송 전 검토

2026-09-23 KST. 사용자는 0.9 운영 배포와 새 안내를 승인했고, 실제 Discord 전송에 앞서 예상 메시지를 보여 달라고 지정했다. 먼저 운영 코드를 0.9로 적용하면서 `ALERTS_HELD=true`로 보류했다. 보류 중 정기 실행은 기존 Durable Object의 기록을 읽고 새 안내 후보만 계산했으며 Discord나 사건 영수증·확인 위치를 변경하지 않았다. 사용자에게 문구를 보여 준 뒤 보류를 해제했다.

## 적용 전

- 운영 0.8 UUID `c345010d-f306-4364-ad46-106b237dbf1a`, 실제 감시 켜짐. 원격 비밀 값 이름 `DISCORD_WEBHOOK_URL`, `X_BEARER_TOKEN` 확인; 값은 읽지 않았다.
- 0.9 소스 검사 및 Windows / Node.js 자동 시험 71개 모두 통과. 모의 Discord로 발송 보류의 무부작용과 실제 전송 시 메시지의 일치를 확인했고, 로컬 workerd에서 보류된 Durable Object가 Discord를 호출하지 않는지 확인했다. 이 시험이 원격 Discord 전송을 증명하지는 않는다.
- Wrangler 운영 설정 묶음 검사는 통과했다. `NOTIFICATIONS_ENABLED=true`, `ALERTS_HELD=true`, `DISCORD_TEST_ENABLED=false`, 기존 `STATE`와 SQLite `MONITOR` 연결, 최종 `*/5 * * * *` 주기를 확인했다.

운영 UUID·보류 중 실제 정기 실행·후보 메시지·비밀 값 보존·실제 발송 건수는 배포 후 기록한다. 승인 전의 Discord 연결 시험은 0.8 한 건이며, 이번 요청에서 추가 시험 메시지를 보내지 않는다.

## 발송 보류 상태의 운영 배포 완료

- 실제 버전 설정: `NOTIFICATIONS_ENABLED=true`, `ALERTS_HELD=true`, `DISCORD_TEST_ENABLED=false`, 기존 SQLite migration `v0-8`와 같은 `MONITOR` 바인딩. 기존 비밀 값 이름 두 개가 남았으며 값은 읽지 않았다.
- 2026-09-23 04:36:08 KST(2026-09-22T19:36:08Z) 첫 실제 Cloudflare 5분 실행: `outcome=ok`, 예외 0, `version=0.9`, 소스 통합 22건, invalid 0, conflicts 0, `held=true`, `wouldNotify=2`, `notifications=0`. 게시본 확인 시각은 `2026-09-22T19:35:33.431Z`다. 이는 실제 사이트를 읽어 기존 0.8 저장 상태를 고려한 **발송 전 계산**을 증명하며, 실제 Discord 도착이나 운영 head 갱신을 증명하지 않는다.

## 발송 보류 해제와 실제 알림

- 사전 제시 후 공개 API를 다시 읽어 두 사건 ID `2102254445082116335`, `2102463847714247142`의 알림 종류·세 줄 문구가 모두 동일함을 확인했다. 이는 보류 진단과 새 조회 사이 변경이 없다는 범위까지의 검증이다.
- 보류 해제 직전 설정 검사에서 시험 파일에 `ALERTS_HELD`의 `true`와 `false` 기대값이 함께 남아 있어 70/71로 실패했다. 설정 자체는 의도한 `false`였다. 중복된 시험 기대값을 제거하고 Windows에서 구문·버전 검사와 71/71 자동 시험 통과를 다시 확인한 뒤 배포했다. 이 실패 중에는 운영 Worker를 다시 배포하지 않았다.
- 실제 발송 운영 UUID `8d366f79-5bd5-46ea-984d-9d7823a30500`, 태그 0.9, 트래픽 100%, 최종 `*/5 * * * *`. 원격 버전에서 `NOTIFICATIONS_ENABLED=true`, `ALERTS_HELD=false`, `DISCORD_TEST_ENABLED=false`, 기존 두 비밀 값 이름을 확인했다. 값은 읽지 않았다.
- 실제 Cloudflare 정기 실행 `2026-09-22T19:40:15Z`(2026-09-23 04:40:15 KST): `outcome=ok`, 예외 0, version 0.9, 통합 사건 22건, 새 알림 **2건 전송 처리**, 과거 보충 항목 3건·만료 신호 1건 제외. 게시본 확인 시각은 `2026-09-22T19:39:33.428Z`다. Discord 전송 코드는 `wait=true` 응답에서 실제 메시지 ID를 받아야 이 2건을 성공으로 센다. 이 실행의 개별 메시지 ID를 로그나 대화에 노출하지 않았으며 사용자의 읽음 상태는 확인하지 못했다.
- 인증 없는 운영 `POST /run`은 401로 차단됐다. 추가 연결 시험 메시지는 보내지 않았다. 기존 0.8 영수증과 `STATE` KV, 원격 X 비밀 값은 되돌리기를 위해 보존했다.

반복 실행의 중복 여부는 다음 절에 기록한다. 이후 새 공지가 나타나면 새 사건의 알림은 승인된 운영 범위이며, 사건 ID별 영수증으로 구별한다.
