# 0.9 리셋 신호·시간 구간 검증

2026-09-23 KST. 0.9 구현과 무발송 시험판 검증 완료. 실제 운영은 0.8이다.

## 후속 확인 위치(head) 검증

사용자 후속 요청으로 `source_head:v1`을 단계별 확인 위치로 추가했다. 원본 게시물의 시각과 ID를 저장하고, 처음 본 ID가 해당 단계의 위치보다 과거이면 보충 이력으로 처리한다. 리셋 확정의 head는 약한 암시의 head와 따로 관리하므로 새로운 암시가 아직 확정되지 않은 실제 리셋을 가리지 않는다. 기존 ID의 새 상태·마감 변경에는 head 차단을 적용하지 않는다. 사이트가 Tibo의 공식 약속을 내놓으면 출처 시각이 오래됐거나 정확한 마감이 없어도 한 번 알리며, 앞선 약한 암시만 전달됐던 같은 ID도 공식 약속 단계로 전진하면 다시 알린다.

- Windows / Node.js: 제품 0.9·npm 0.9.0 구문·버전 검사 통과, 전체 **69개 자동 시험 통과**. 과거 ID·동일 시각의 ID 순서, 같은 조회의 여러 새 사건, 0.8 기록 복원, 재시작, 중간 Discord 실패와 잘못된 응답에서 head가 잘못 앞서지 않는지 확인했다. 특히 Tibo의 날짜 없는 공식 약속과 앞선 암시 뒤의 약속 승격을 별도로 검사했다. Discord 응답은 모의다.
- 로컬 workerd / SQLite Durable Object: 최초 자료와 head가 함께 저장되고 보호된 진단에서 저장된 확인 위치를 읽었다. 실제 Cloudflare 장기 유지와 실제 Discord 전송은 이 로컬 실행으로 증명하지 못한다.
- 실제 Cloudflare 격리 0.9 시험판 UUID `916b7065-aa8b-4f69-ae4c-ea3f574027a9`에서 무발송 `/preview-poll`을 한 번 실행했다. 응답: 22건, invalid 0, conflicts 0, wouldNotify 2, notifications 0, mode=observe. head에는 reset·reset-sign·reset-watch·banked 단계별 마지막 ID와 시각이 저장돼 있었다. 이는 원격 SQLite 저장과 기존 이력 초기화·진행 중인 예고 선택을 증명하나 운영 0.8 저장소에서의 실제 이행은 아직 증명하지 못한다.
- 임시 진단 토큰은 다시 삭제했다. 원격 운영 배포와 실제 Discord는 변경하지 않았다.
- 같은 실제 Cloudflare 시험판의 후속 요청에서 **먼저** 읽은 head가 위 초기 저장 내용과 일치했고, 동일 목록을 다시 처리한 `/preview-poll`은 `wouldNotify=0`, `notifications=0`, `already_seen=21`, `ineligible=1`이었다. 이는 원격 저장소가 요청 사이 확인 위치를 유지하고 같은 자료를 다시 알림 후보로 만들지 않았음을 증명한다. 새 사건이 실제 등장했을 때 Discord 전달까지 증명하는 결과는 아니다.
- 최종 알림 제목을 Tibo의 약속이라고 명시한 0.9 시험판 UUID는 `a9532a5e-d887-49e7-a6ba-93ae6440a41e`다. 실제 API의 약속 신호 `2102254445082116335`를 진단했으며 **“Tibo가 약속한 Codex 리셋 예고 — 완료 아님”**, 예고 마감 2026-09-23 15:59:59 KST를 표시했다. 재조회는 저장된 같은 head와 알림 후보 0건을 확인했다. 임시 토큰이 일부 Cloudflare 지점에 늦게 반영되며 인증 401이 났지만, 인증된 요청을 성공시켜 실발송 0건과 토큰 제거를 확인했다. 401은 감시·Discord에 도달하지 않았다.
- `wrangler secret list`에서 시험판의 비밀 값 목록은 `[]`이었다. 두 원격 시험 모두 Windows에서 요청했으며 Cloudflare 내부 실행 운영체제는 공개되지 않아 특정 OS 동작의 증거로 해석하지 않는다.

아래 최초 60개 시험·이전 시험판 UUID는 후속 head 구현 전의 단계별 기록이다. 이 절의 최신 결과를 우선한다.

## 확인한 공개 정보

- `/api/forecast.official_signal`에 공식 예고가 있고, 중첩 window가 구간·마감·중심 시각을 제공한다. 실제 사이트의 `home-countdown.js`도 이 필드로 마감을 표시한다.
- 관측한 예고 ID `2102254445082116335`는 timeline에서 announcement_state=none이지만 forecast에서는 dated_commitment다. 0.8의 확정 발표만 선택하는 규칙으로는 누락되는 사례다.
- 관측한 deadline은 `2026-09-23T06:59:59.999Z`, 한국 시간 2026-09-23 15:59:59.999다. 초 단위 알림에서는 **15:59:59 KST까지 · 확정 시각 아님**으로 표시한다.
- 사이트의 banked 목록은 credits·kind=banked·reset_kind=banked·banked_state로 구성된다. unknown은 지급 여부 미확인이지 관련 신호가 없다는 뜻이 아니다.
- 최신 암시·공개 feed의 candidate/signal/banked/reset·사이트가 공개한 완료된 teasing 판정도 처리한다. 통계 확률·요일별 빈도만으로 알림을 만들지 않고, 게시물 본문을 자체 해석하지 않는다.

## 전환 시 주의할 동작

- 0.8의 같은 Durable Object·사건 ID·상태 순위·영수증을 유지한다. 새로 적격이 된 오래된 unknown 이력을 일괄 재발송하지 않는다.
- 현재 활성 예고·암시는 게시 후 1시간이 지나도 한 번 알린다. 이후 새 상태나 미래 마감 변경을 추가 안내한다. 기한 없는 공식 예고에 임의의 만료 나이를 부여하지 않는다.
- 시간 경과만으로 리셋 완료를 만들지 않는다. 같은 ID가 확인된 발표 상태가 되어야 다음 단계의 알림을 보낸다.
- 새로운 0.9 운영 적용 승인을 받으면 해당 버전으로 전환할 수 있다. 실제 Discord 연결 시험이 필요하다면 별도로 허락받으며, 이전 시험 승인을 재사용하지 않는다.
- 지식 범위는 current-project다. Hive 프로젝트 등록 목록에 이 프로젝트가 없어 결정을 사용자 전역으로 확대하지 않고 계획·검증 문서에 보존했다.
